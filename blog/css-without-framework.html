手写 CSS 的四个决定

2026 年 10 月 17 日 · 约 4 分钟读完

不用框架写 CSS，很容易滑向两种结局：要么堆成一团无法维护的样式，要么过度设计出一套没人用的"设计系统"。这个站点选了中间路线，只做了四个决定。

一、用自定义属性管理配色

所有颜色都收进 :root，组件只引用变量。换主题时不用改任何组件样式。

:root {
  --bg: #ffffff;
  --fg: #1a1a1a;
  --muted: #6b7280;
  --line: #e5e7eb;
  --accent: #2563eb;
}

二、深色模式跟着系统走

不做一个切换按钮，直接用 prefers-color-scheme 覆盖变量。少一个按钮、少一段 JS、少一份本地存储，也少一个"用户忘了切换"的困惑。

@media (prefers-color-scheme: dark) {
  :root {
    --bg: #0f1115;
    --fg: #e8e8e8;
    --line: #262a33;
  }
}

三、打印样式是正式的输出格式

简历总有人会打印或导出 PDF。默认打印会带上深色背景和链接下划线，所以单独写了 @media print：强制浅色、缩小字号、避免条目跨页断开。

@media print {
  .item { break-inside: avoid; }
  a { color: #000; }
  .site-header, .site-footer { display: none; }
}

四、不写 JavaScript

没有折叠菜单，没有滚动动画，没有"回到顶部"。代价是移动端的导航只能平铺成四个链接；收益是页面不会闪、不会因为脚本报错而白屏。

导航只有四项，平铺完全放得下。如果以后超过五项，再考虑用 <details> 做无脚本的折叠菜单。

结果

整个样式表大约 6 KB，覆盖了首页、列表、文章和打印四种场景。没有构建、没有压缩、没有 PostCSS——浏览器能直接读。
